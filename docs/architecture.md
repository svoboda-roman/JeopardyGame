## Overview

JeopardyGame is a monorepo containing a realtime Jeopardy-style game. The
frontend is a single-page app; the backend is a typed HTTP + WebSocket server
that talks to a PostgreSQL database. Types flow end-to-end from the database
schema through the API to the client without manual duplication or codegen.

## Directory layout

```
JeopardyGame/
├── apps/
│   ├── server/          # Backend: Elysia HTTP/WS API + Drizzle ORM
│   └── web/             # Frontend: React SPA (Vite + TanStack Router)
├── docs/                # Project documentation (this folder)
├── biome.json           # Lint + format config (repo-wide)
├── package.json         # Workspace root; tooling deps only
├── bun.lock             # Single lockfile for all workspaces
├── LICENSE
└── README.md
```

`apps/*` are bun workspaces. Each app owns its own runtime dependencies; the
root `package.json` only carries repo-wide tooling.

### `apps/server`

```
apps/server/
├── package.json
└── tsconfig.json
```

Source files will live under `src/` (not yet scaffolded). Planned layout:

```
src/
├── index.ts             # Elysia app entry; exports `App` type for Eden
├── routes/              # Elysia route modules
├── db/
│   ├── schema.ts        # Drizzle table definitions
│   └── client.ts        # pg pool + drizzle instance
└── lib/                 # Shared server-side helpers
```

The Elysia app exports its inferred type (`export type App = typeof app`).
The `web` app imports that type via Eden's `treaty<App>(...)` for end-to-end
type safety — no codegen step.

### `apps/web`

```
apps/web/
├── index.html           # Vite entry
├── vite.config.ts       # Vite + TanStack Router + Tailwind plugins
├── components.json      # shadcn/ui config
├── package.json
├── tsconfig.json
├── public/              # Static assets
└── src/
    ├── main.tsx         # React entry; mounts <RouterProvider />
    ├── styles.css       # Tailwind import + theme tokens (shadcn)
    ├── routes/          # File-based routes (TanStack Router)
    │   ├── __root.tsx
    │   └── index.tsx
    ├── components/
    │   └── ui/          # shadcn/ui primitives (button.tsx, ...)
    └── lib/
        └── utils.ts     # `cn()` helper, etc.
```

`routeTree.gen.ts` is generated by the TanStack Router Vite plugin on
`bun dev` / `bun build` — do not edit by hand and do not commit it.

Path aliases: `#/*` and `@/*` both map to `src/*` (see `tsconfig.json`).

## Tech stack

### Runtime & tooling
- **[Bun](https://bun.sh/)** — JavaScript runtime, package manager, and
  workspace orchestrator. Single lockfile at the repo root.
- **[TypeScript](https://www.typescriptlang.org/)** — strict mode, bundler
  module resolution, hoisted to the workspace root.
- **[Biome](https://biomejs.dev/)** — formatter + linter for the entire repo.
  Respects `.gitignore` automatically.

### Backend (`apps/server`)
- **[Elysia](https://elysiajs.com/)** — Bun-native HTTP + WebSocket framework
  with first-class type inference.
- **[Drizzle ORM](https://orm.drizzle.team/)** with **`pg`** driver —
  PostgreSQL access. Schemas live in `src/db/schema.ts`; inferred types feed
  directly into Elysia handlers.
- **[drizzle-kit](https://orm.drizzle.team/kit-docs/overview)** — migrations.
- **[dotenv](https://github.com/motdotla/dotenv)** — environment variable
  loading.
- **[tsx](https://tsx.is/)** — used where direct `bun` execution is not
  desired (e.g. drizzle-kit scripts).

### Frontend (`apps/web`)
- **[React 19](https://react.dev/)** — UI library.
- **[Vite](https://vitejs.dev/)** — dev server and bundler.
- **[TanStack Router](https://tanstack.com/router)** — fully type-safe,
  file-based routing. SPA mode (no SSR; the realtime gameplay does not
  benefit from it, and SSR would compete with the Elysia server).
- **[Tailwind CSS v4](https://tailwindcss.com/)** via `@tailwindcss/vite` —
  utility-first styling. No `tailwind.config.ts`; theme tokens live in
  `src/styles.css`.
- **[shadcn/ui](https://ui.shadcn.com/)** — component primitives copied into
  `src/components/ui/`. Built on `@base-ui/react`, `class-variance-authority`,
  `clsx`, `tailwind-merge`, and `tw-animate-css`. Theme preset: `b6sCXmnxJY`.
- **[lucide-react](https://lucide.dev/)** + **[hugeicons](https://hugeicons.com/)** — icon sets.
- **Fonts**: Figtree (sans), Montserrat (heading), self-hosted via
  `@fontsource-variable`.
- **Vitest** + **@testing-library/react** + **jsdom** — component testing.

### Type flow
```
Drizzle schema  ──►  Elysia handlers  ──►  export type App
                                              │
                                              ▼
                                       treaty<App>()  ──►  React components
                          (in apps/web, type-only import from `server`)
```
The web app declares `apps/server` as a workspace dependency so it can do
`import type { App } from 'server'`. The import is erased at build; no
server code is bundled into the client.

## Running

From the repo root:

```bash
bun install            # install all workspaces
bun run lint           # biome check
bun run format         # biome check --write
```

Per-app:

```bash
cd apps/web && bun dev       # Vite dev server on :3000
cd apps/server && bun dev    # (script TBD)
```

## Conventions

- **One lockfile.** Never commit `bun.lock` inside an app folder.
- **Workspace-only deps at the root.** Only repo-wide tooling (Biome,
  TypeScript) lives in the root `package.json`. App runtime deps go in
  the app.
- **No SSR.** The web app is a pure SPA. Server-rendered routing would
  duplicate work Elysia already owns.
- **Generated files are not committed.** `routeTree.gen.ts`, `node_modules/`,
  build output, etc.
